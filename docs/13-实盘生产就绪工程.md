## 一、摸底结论（2026-09-19）

## 二、改造方案（分批）

### 批次 1：包级能力（并行，互不触碰 main.go）

- **T1 execution 包**：订单状态 JSONL 事件溯源持久化 + 启动恢复 API + 限流错误识别退避。
- **T2 okx/binance 适配器**：REST 客户端限速器；OKX 启动时钟偏移校准（/public/time）；WS backoff 复位。
- **T3 risk/portfolio 包**：权益看门狗（日损巡检与 CheckOrder 共用同一规则）；ApplyFill 按 FeeCcy 分账；对账结果结构化。
- **T4 config 包**：费率可配置（默认对齐 OKX 8/10 bps）；新增 watchdog / reconcile / ratelimit 配置节。

### 批次 2：编排接线（main.go + dashboard，单 agent 串行）

- **T5 启动生命周期**：journal 重放 → 拉交易所挂单合并 → Seed → 强制账户对账（不通过即 RECONCILE_BLOCK + 告警）→ 看门狗启动 → Poller.OnError 接告警 → SIGTERM 优雅退出（停信号→可选撤单→落盘）→ Kill 复位前置对账 → dashboard 展示对账状态。
- **T6 策略运行态持久化**：grid/trend 状态经 state 落盘与恢复。

### 批次 3：验证收尾

- 全量测试 + `-race`；paper/本地冒烟；更新 docs/12 路线图状态与 README；部署物（systemd 示例）。

## 三、设计决定（子任务必须遵守）

1. **持久化选型**：订单事件 JSONL（`data/state/orders.jsonl`，事件溯源重放），不进 SQLite——量级小（网格日数百事件）、可读可审计、与拒单台账同风格。
2. **启动顺序（不可变）**：重放 journal → GetOpenOrders 合并（孤儿单采纳并 claimed 标记）→ Seed 余额 → 账户对账 → 通过才允许交易（对账失败保持 RECONCILE_BLOCK，人工介入）。对应 docs/08 "崩溃恢复后必须先对账再恢复交易"。
3. **限流**：`exchange.ErrRateLimited`（exchange/errors.go）为唯一信号；适配器识别限流码返回该错误；execution 对其可重试 + 更长退避；适配器内置保守 token bucket。
4. **权益看门狗**：日损规则从 CheckOrder 抽出共用；看门狗周期巡检触发 Kill.Trip（OnTrip 已接撤单+通知链）。dayStartEq 持久化到 state，Seed 后用真实 mark 重设基线。
5. **费率默认值**：spot maker 8 bps / taker 10 bps（OKX L1），配置可覆盖；回测沿用配置，禁止再硬编码。
6. **红线不放松**：所有新路径必须过 risk.CheckOrder；Kill 触发链保持撤单+通知；live 门禁不变。

## 五、Review 修复记录（2026-09-19 第二轮）
