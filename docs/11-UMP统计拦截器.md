# 11. UMP 统计拦截器（信号情境胜率）

> 借鉴 abu UMP（失败交易拦截）思路的统计版实现——不用机器学习，用可解释的情境分桶统计。
> 核心纪律：**拦截器本身也是策略，必须过样本外验证才允许部署**（docs/01）。

## 一、机制

信号落地前提取三个情境特征（全部只用决策时点前的数据，防前视）：

| 特征 | 口径 | 离散化 |
|---|---|---|
| RSI | Wilder RSI(14) | 10 桶（每 10 一桶） |
| 距前高距离 | close / 前 20 根最高价 − 1 | 10 桶 |
| 波动率分位 | 当前 ATR14/close 在过去 50 根分布中的分位 | 10 桶 |

拦截规则（`ump.Filter`）：历史同情境（三桶相同）交易数 ≥ minSamples（默认 20）
**且** 胜率 < minWinRate（默认 35%）→ 拦截该信号。
样本不足放行——证据不足不判罪。

## 二、拦截器自身的样本外验证（`ump.ValidateOOS`）

时间对半：前半样本建统计 → 后半样本模拟"启用拦截"：
- `TestWinRateAfter > TestWinRateBefore` 且拦截数 > 0 → 拦截器可用
- 否则（提升 ≤ 0 或零拦截）→ 拦截器拟合了历史噪音，**不得部署**

## 三、研究工作流

```bash
quantforge umpcheck -config config.json -strategy trend [-min-samples 20]
```

样本 → 回测 → `ump.PairTrades`（成交配对成带情境的交易样本，未平仓不入库）
→ `lab.UMPCheck`（OOS 自验证）→ 三档输出：可用 / 零拦截无增量 / 未过验证不得部署。

## 四、部署条件（未达成，记录于 2026-08-28）

serve 暂不接入自动拦截。部署门槛：
1. 长样本（网络可达后 `fetch` 拉取）上 `umpcheck` 稳定输出"可用"；
2. 部署后先在 paper 模式观察拦截行为与复盘留痕；
3. 拦截器统计需要持久化与滚动重建（当前 `Filter.Snapshot/Restore` 已具备，state 集成待部署时做）。

当前固定样本（300 根 1H）上 trend 仅 4 笔交易——样本不足以下任何结论。
