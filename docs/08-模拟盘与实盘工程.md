# 模拟盘与实盘工程

## 一、交易阶段模型

- execution_mode 三档：`research` / `paper` / `live`，每次运行显式声明，由配置 + 人工批准开启。
- 同构原则：三个阶段共用同一套策略代码、信号管道、风控规则与订单状态机，只替换执行适配器（回测撮合器 / 模拟撮合器 / 券商或交易所网关）。风控路径完全一致，禁止"实盘版多一层、回测版少一层"。
- 晋级矩阵：
  - research → paper：样本外检验通过、成本/滑点假设完整、无前视与数据泄漏、试验台账齐全；
  - paper → live：模拟盘连续运行达标（≥1 个完整月且覆盖趋势/震荡/高波动多种行情）、风控拦截与 Kill Switch 演练通过、对账与监控告警可用、人工书面批准；
  - live 内部加仓：每次视作一次新晋级，须回顾当前级绩效与偏差归因。
- 降级路径：任何异常可一键 live → paper（策略继续跑但不下真单），保留观察数据用于复盘。

## 二、模拟盘（paper）要点

- 撮合真实性：用实时行情 + 滑点/部分成交模型，禁止"按收盘价足额成交"式简化；触板不可成交规则与实盘一致（涨停买不进、跌停卖不出）。
- 延迟注入：按目标市场的真实下单往返延迟模拟信号 → 成交时差，检验策略对延迟的敏感度。
- 偏差账本：持续记录 signal → fill 延迟、实际滑点、拒单率、部分成交率，与回测假设对比形成偏差报告——这是决定能否晋级实盘的核心证据。
- 模拟盘跑得好只证明"工程管道正确 + 策略没被延迟和滑点打死"，不证明赚钱。

## 三、实盘执行工程

- 订单状态机：`NEW → SUBMITTED → PARTIALLY_FILLED → FILLED / CANCELLED / REJECTED / EXPIRED`；每个回报回调幂等处理（按 order_id + client_order_id 去重）。
- 重试纪律：重试有次数上限 + 指数退避；回报延迟时禁止盲目补发整单（光大乌龙指教训：2 秒重发 234 亿）；先查单后补单。
- 下单前置校验清单：可用资金 ≥ 订单金额；可卖数量 ≥ 卖出数量（T+1 剔除当日买入）；价格未触板；单笔/单日/总敞口/频率限额内。
- 限价保护：极端行情禁用市价单，用限价单或"对手价 − 保护比例"。
- Kill Switch：一键撤所有挂单 + 平仓 + 停机，物理可触发（不依赖图形界面），停机后自动进入对账模式。
- 对账（reconciliation）：本地订单簿与券商/交易所回报定期核对，资金与持仓不一致即告警并冻结新下单，人工介入前不恢复。
- 密钥与权限：API Key 只授交易权限、禁提币权限；密钥走环境变量/密管，不入库不进日志；IP 白名单。

## 四、监控与告警

- 行情看门狗：买卖价差 > 均值 5 倍报警；盘口深度（买一至买五）萎缩 90% 报警停机。
- 策略看门狗：当日亏损 > 阈值（如 5%）强制平仓停机；持仓/敞口偏离预期告警；成交频率异常（可能是重试风暴）告警。
- 系统看门狗：进程存活、行情断流、延迟与错误率监控；崩溃恢复后必须先对账再恢复交易，不自动盲跑。
- 所有告警留痕，处置动作与人工确认写入运维日志。

## 五、资金灰度与事故处置

- live 起步资金 ≤ 总计划的 10%，按周期（如月）达标后逐级加仓；任一级回撤超限退回上一级资金规模。
- 事故 playbook：异常成交/异常行情 → 触发 Kill Switch 或降级 paper → 冻结策略 → 对账核对 → 人工处置 → 复盘归档（根因、损失、修复、防复发）。
- 变更管理：参数/代码变更走审批留痕（修改人/原因/影响/回退方案）；live 的变更必须先在 paper 验证一个完整周期。
- 永远保留人工干预通道：任何自动逻辑之上，人可以随时停机、减仓、降级。
