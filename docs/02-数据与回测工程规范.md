# 数据与回测工程规范

## 一、三层数据架构与快照机制

- **实时层**：尝试拉上游接口，异常完整记录到 errors，禁止失败后静默伪装正常加载。
- **快照层**：固化单次研究输入。保存时**双写**：同一数据包同时写入历史归档目录（`snapshots/history/<name>/<history_id>.json`）与当前指针文件；manifest 数据清单登记完整性。
- **固定样本层**：完全离线的兜底数据，供离线兜底与回归测试。
- 离线读取优先级：完整快照 > 完整固定样本 > 残缺快照（完整性优先于新鲜度）。
- 快照四要素元数据：`saved_at`、`origin`、`history_id`、`history_path`；manifest 记录 `complete`、`reason`、`latest_path`。
- **追溯链（逆向复核标准路径）**：报告结论 → 数据集名称 → 当前指针 → history_id 历史归档 → 元数据清单。任一环节断裂，结论标记待核实。
- 量化口径：新鲜度 age = now − saved_at（取自元数据，禁用文件修改时间）；覆盖率 coverage = complete/expected；同批快照 max(saved_at) − min(saved_at) ≤ Δ 否则须标注分段采集。快照≠备份：快照服务复现与审计，必须留多版本。

## 二、清洗原则与数据契约

- 核心原则：**能解释的转换才做，不能解释的缺口记为缺失**。`""` / `"N/A"` / 无法转换 → None，禁止填 0（0 是事实，缺失是未知）；"3.2%"、千分位须在显式规则层处理并记录单位。
- 时间字段不混用：`tsSec`（标准化秒级 UTC，指标/回测用）、`openTime`（原始时间桶）、`observed_at`（可见时间）、`updated_at`（落盘时间）、`date`（仅展示，不作唯一键）。
- **K 线唯一键：`exchange + symbol + interval + openTime`**。完全重复可去重留一条；同键不同 close 冲突值须拒绝；中间缺桶切断窗口；未收盘 K 线只可展示，禁入指标与回测。
- 三层放行矩阵：展示层容忍缺失；指标层关键字段缺失即阻断；回测层任何可能改变买卖点/收益/回撤的输入不放行。
- 主动注入六类污染样本验证：重复时间戳、逆序、缺失字段、字符串数值、价格越界、时间漂移；系统须在错误输入前停下而非静默修复。

## 三、目录结构约定

`src/`（dashboard 信号与 API / backtest 回测 / factor_mining 因子 / risk 风控 / research 报告 / strategy_engine 策略 DSL）+ `data/`（固定离线样本）+ `tests/`（可执行验证）+ `docs/samples/`（假设卡、就绪记录模板）+ `vendor/`（只读上游对照，禁止被 src 导入）。`.env.example` 只声明变量名，密钥不入库。工作区可交接四开关：path_ok ∧ sample_ok ∧ command_ok ∧ limitation_ok。

## 四、事件驱动回测引擎

**主循环推进顺序**（每根 K 线）：结算上一轮挂单 → 当前 K 线写入历史上下文 → 调用策略生成 OrderIntent → 风控校验+撮合 → 按当前收盘价记录权益。策略只能读 `ctx.history` 当前及历史，无未来数据。

- 订单分流：市价单即时成交（滑点模型定价）；IOC/FOK 不满足即失效不留挂单；GTC 限价单与止损单入 pending 队列逐轮结算触发。
- 风控双拦截点：新订单提交瞬间 + 存量挂单触发成交瞬间；拦截写入 `risk_rejections`（含 rule_id、reason），不静默丢弃。
- **三类审计记录必须并存**：`trades`（成交）、`pending_orders`（期末挂单快照）、`risk_rejections`（拒单）。仅看成交表会掩盖大量违规下单行为；测试场景必须同时出现三类分支才算覆盖。
- 模块解耦：行情、策略、订单、撮合、组合、成本、风控分层，状态单向流转。

## 五、指标计算规范

- 权益：`equity = cash + position × close`，逐 K 线留检查点。
- 净收益：`r_net = r_gross − fee − slippage − funding`；零成本必须标注"简化口径、成本未建模"，不可写"成本为零"。
- 最大回撤：基于权益曲线逐点复算，`MDD = min(E_t/peak_t − 1)`，不可用标的价格跌幅替代；与收益须来自同一条曲线，符号约定须一致。
- Calmar = 总收益% / |MDD%|（须声明口径，跨系统比较前核对是否年化、窗口、正负号）。
- Sharpe：逐期权益收益均值 / 样本标准差 × √periods_per_year（日频 365）；解释必须绑定 periods_per_year、total_trades、max_drawdown_pct、num_trials；须注明未覆盖下行半方差与尾部损失。
- 多次试验后用 PSR/DSR 审计：num_trials 增大 DSR 快速下降，冠军 Sharpe 不能直接当能力。

## 六、报告可追溯三率

- `claim_traceability`（重大主张有来源比率）、`metric_attribution`（指标有计算来源比率）、`limitation_coverage`（限制声明覆盖率），**三者均须 = 1.0 方可发布**。限制项至少含：样本范围、参数、成本假设、自动文本参与位置、失败路径、不可外推边界，且与结论同页。
- 主张账本字段：claim / evidence_layer / source_path / decision / limitation；路径须能在 JSON 报告中 resolve。

## 七、未来函数与过拟合的工程识别

- AST 静态扫描错误级规则：`shift(-N)`、`np.roll(..., -N)`、`ctx.future_*`、`history[正数]` 需人工说明；DSL 安全检查（禁危险 import）与前视检查**分开验收**，通过安全门 ≠ 无前视。
- 三段固定反例自测：安全空策略（全过）、危险导入（DSL 拦）、前视位移（前视门拦），三例输出须稳定。
- 数据泄漏六形态：全样本预处理（归一化/填补只能拟合于训练段）、标签泄漏、发布时间泄漏、选择泄漏（看测试集后改规则）、样本池泄漏（幸存者）、预训练知识泄漏（LLM 训练语料含未来信息）。
- 过拟合信号：样本内 Sharpe 远高于样本外；训练段冠军在测试段频繁掉队；参数邻域扰动后表现漂移。处置：冻结切分重评、补试验日志、降级为探索性观察；污染样本作废重建特征，不得"降级使用"。
