# 12. 平台差距分析与路线图

> 2026-08-28 诚实盘点：对照可运营的量化交易平台，缺什么、按什么顺序补。
> 现状代码规模：Go 源码 6.4k 行 + 测试 6.8k 行（23 包 -race 全绿），前端 750 行。

## 一、现状定位（先说清"是什么"）

后端是正经量化架构：数据面（OKX REST + SQLite 库 + 快照双写 + 质量校验）→
研究面（事件驱动回测 + walk-forward/参数高原/成本敏感性 + UMP + Kelly 闭环）→
执行面（风控前置 + 幂等提交 + 对账循环 + 三级模式）→ 运维面（小时复盘 + state 持久化）。

**真正的短板**：前端只露出 30% 能力（单页 750 行，无路由无推送）；
后端缺实时推送、多标的、告警、组合层四块硬骨头。

## 二、差距清单（按层）

### 数据面
| # | 缺口 | 影响 | 量级 |
|---|---|---|---|
| D1 | **WebSocket 实时行情**（现为 15s REST 轮询） | 信号延迟、执行质量上限低 | 大 |
| D2 | 盘口深度（orderbook/spread） | 网格吃价差、滑点模型无输入 | 中 |
| D3 | 多标的（单 BTC-USDT 假设遍布 app/config/页面） | 分散化=最免费的风控，做不了 | 大 |
| D4 | 数据源容灾（binance 仅占位） | OKX 单点 | 中 |
| D5 | 1H 全历史未拉完（中断在 2019-09） | 1H 假设卡结论不完整 | 小 |

### 策略与研究面
| S1 | 策略不可插拔：Registry 存在但 serve 硬编码 grid | 只有 1 个策略在跑（trend/lab 全在研究侧） | 中 |
| S2 | 参数管理：改网格参数要改 config 重启 | 运营不可能 | 中 |
| S3 | 研究工作台：lab 四件套是 CLI/库，页面只有一个"跑回测"按钮 | 研究与运营割裂 | 中 |
| S4 | 组合层：多策略资金分配/风险预算（grid+trend 并行） | 单策略单标的=单点收益来源 | 大 |
| S5 | UMP 只拦 grid 买单（trend 未验证启用） | 拦截器覆盖面 50% | 小 |

### 执行与交易面
| E1 | 手动撤单/下单（应急手段，页面无） | 异常时只能等 Kill | 中 |
| E2 | 成交历史页面（只有挂单） | 复盘靠文件 | 小 |
| E3 | 对账差异展示/通知（ReconcileOnce 静默） | 账实不符不可见 | 小 |

### 风控面
| R1 | **告警通道**：Kill/断流/拒单只进日志 | 人不能盯着页面 24h | 大 |
| R2 | 实时权益曲线页面（数据在复盘里，无图） | 运营感知差 | 小 |
| R3 | 风控限额只读（页面不能调） | 可接受（保守），低优 | 小 |

### 前端工程
| F1 | 无路由，功能堆一页；750 行已显拥挤 | 加功能会烂 | 中 |
| F2 | 无推送（全轮询） | 3-15s 延迟感知 | 中 |
| F3 | 无登录页（Token 靠 localStorage 手填） | 多人/远程不可用 | 小 |
| F4 | 无移动端适配 | 低优 | 小 |

### 工程质量
| Q1 | **无 CI**（GitHub Actions：test/lint/build） | 开源协作基线缺失 | 小 |
| Q2 | 无 Dockerfile/部署文档 | 别人跑不起来 | 小 |
| Q3 | 无 metrics（prometheus 等） | 复盘日志代替，可接受 | 小 |

### AI 层（docs/09 规划 vs 现实）
| A1 | 四角色流水线未接入系统（.claude 定义闲置） | 规划与实现脱节 | 中 |
| A2 | Charles 情报采集未实现（sources.json 无消费者） | 同上 | 中 |
| A3 | LLM 信号层（docs/03）未实现 | 解释层空缺 | 中 |

## 三、路线图（按"赚钱与活着"优先级）

### P0 活着与感知（建议先做，约 2-3 轮迭代）
1. **告警通道**：Kill/断流/连续拒单 → Telegram Bot（R1）——出事必须第一时间知道
2. **实时权益曲线 + 成交历史页**（R2/E2）——运营感知的基本盘
3. **手动撤单/下单**（E1）——应急控制
4. **WebSocket 行情**（D1）——收盘信号从 15s 级到秒级
5. 前端拆路由（F1）——为 P1 页面腾地方

### P1 赚钱面（研究→运营闭环，3-4 轮）
6. **策略可插拔**：Registry 落地 serve + 页面选策略/参数（S1/S2）
7. **组合层**：grid+trend 双策略资金分配 + regime 路由开关（S4，回测证据已有一半）
8. **研究工作台页面**：WF/参数高原/UMP 结果展示对比（S3）
9. 多标的架构（D3）——config 数组化、Poller/账本/页面多实例
10. 1H 全历史补全 + 假设卡重验（D5）
